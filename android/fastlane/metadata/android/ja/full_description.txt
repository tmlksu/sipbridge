SIP Bridge は、セルフホスト型の <b>sipbridge</b> 用 Android クライアントです。
<b>ルーターのポートを一切開けず</b>、<b>端末で平文 UDP 5060 を待ち受けることもなく</b>、
外出先から自宅の SIP 内線を使えるようにします。

<b>relay を自分で動かす必要があります。</b> このアプリ単体では何もできません。
自宅 LAN 内の PBX の隣で動かす小さな Go 製サービス <i>sipbridge relay</i>
(Docker イメージあり) と通信します。relay は SIP サーバに普通の内線として
REGISTER し、アプリに対しては認証付きの WebSocket を 1 本だけ提供します。
レジストラは何でも構いません: Asterisk、FreePBX、あるいは
ひかり電話対応ルーター (NTT HGW) の内蔵 SIP サーバでも動きます。

<b>仕組み</b>

アプリ --WSS (JSON + RTP フレーム)--> リバースプロキシ / トンネル --> relay
--LAN 内の SIP + RTP--> PBX

端末は LISTEN ソケットを一切開きません。シグナリングと音声を 1 本のアウトバウンド
TLS WebSocket に相乗りさせるため、CGNAT 配下でもホテルの Wi-Fi でも通ります。

<b>機能</b>

* 発着信 (G.711 PCMU/PCMA)
* キーパッド、通話履歴、端末内の連絡先からの名前解決 (任意)
* ロック画面上に出る全画面の着信通知
* 常駐モード: フォアグラウンドサービスが WebSocket を張り続ける
  (常時給電のタブレットや据え置き端末向け)
* 複数 SIP アカウント。アプリから設定し、relay 側が保持する
* 設定は暗号化して保存 (EncryptedSharedPreferences)

<b>このビルドについて</b>

<i>foss</i> フレーバーです。Google Play 開発者サービスも Firebase も含まないため、
<b>push 通知は使えません</b>。着信を受けるには常駐モードで接続を維持する必要が
あります。常時電源が入っている端末での利用を想定した構成です。

<b>プライバシー</b>

アプリが通信するのは、設定した relay の URL だけです。解析も送信も第三者サービスも
ありません。音声は TLS WebSocket の中を通って自分の relay に届きます。ただし CDN や
トンネル事業者で TLS を終端している場合、その事業者からは音声が見えます。連絡先の
名前解決を有効にした場合も、照合は端末内で完結し、端末外には出ません。

導入手順・relay のソース・プロトコル仕様はソースリポジトリにあります。
